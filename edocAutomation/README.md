# edoc — BUU eDoc CLI

A command-line app to triage and sign documents on the BUU e-Document system
(<https://doc.buu.ac.th/docweb>). It scrapes your inbox, ranks documents with Claude,
writes a human-editable queue file, and signs only the documents you authorise.

The flow is deliberately split in two so a human always reviews before any signing happens:

1. **Fetch** — `edoc` logs in, reads every document, asks Claude to rank them, and
   writes the result to [`documents.md`](#the-queue-file-documentsmd).
2. **Review** — you open `documents.md` in your editor, mark anything you don't
   want signed as `skip`, then flip the queue gate from `PROVISIONAL` to `READY`.
3. **Sign** — `edoc --sign` reads the queue, signs every document still marked
   `signing`, then moves the file into `log/` with a timestamped name.

---

## Install

Requirements: Python ≥ 3.11, [uv](https://github.com/astral-sh/uv), Playwright
browsers installed.

```bash
git clone <repo>
cd edocAutomation
uv sync                                 # installs the package + deps
uv run playwright install chromium      # one-time, downloads browser
```

This installs an `edoc` console script. From inside the project run it via
`uv run edoc …`. (If you `uv pip install -e .` into a venv that's on your PATH,
you can drop the `uv run` prefix.)

## Configure

Copy `.env.example` to `.env` and fill in:

```dotenv
EDOC_USERNAME=your_buu_username
EDOC_PASSWORD=your_buu_password
INBOX="ผศ. ดร. ณยศ คุรุกิจโกศล"     # your shortcut name in ทางลัด
ANTHROPIC_API_KEY=sk-ant-...
HEADLESS=false                       # default browser mode
```

`HEADLESS` accepts `true`/`false`/`1`/`0`/`yes`/`no`. CLI flags `--headless`
and `--headful` override it for a single run.

## Daily workflow

```bash
# 1. Fetch + rank. Writes documents.md and updates documents_data.json (cache).
uv run edoc

# 2. Open documents.md in your editor. For each block:
#       - **Action:** `signing`     ← change to `skip` to leave a doc untouched
#       - **Command:** ดำเนินการตามเสนอ   ← edit the signing command if needed
#    Then change the top-of-file gate:
#       **Queue Status:** `PROVISIONAL`   ← change to `READY` to authorise

# 3. Sign. Run dry first to verify selectors are healthy.
uv run edoc --sign --dry-run            # fills each form, clicks Cancel
uv run edoc --sign                      # real signatures
```

After a real `--sign` run, the queue file is moved to
`log/documents_<YYYY-MM-DD>_<HH-MM-SS>.md` so you have an audit trail and the
project root is always clean for the next fetch.

## CLI reference

```
edoc                                    # default: fetch + analyze
edoc --sign                             # sign every doc marked `signing`
edoc --sign --dry-run                   # full flow but Cancel instead of OK

# global flags
--headless / --headful                  # override .env HEADLESS
--inbox NAME                            # override .env INBOX
--file PATH                             # default ./documents.md
--limit N                               # cap docs processed (testing)
--from-cache                            # (fetch only) skip scrape, re-run AI
                                        #   on existing documents_data.json
--force                                 # (fetch only) overwrite documents.md
                                        #   even if Queue Status is READY
-v, --verbose                           # also echo log lines to stderr
```

### Exit codes

| Code | Meaning |
|------|---------|
| 0    | success |
| 1    | runtime error (browser crash, partial sign failure, AI parse error) |
| 2    | user input error (missing file, bad flag combo, queue not READY) |

These make `edoc` clean to drive from automation runners (OpenClaws, cron, CI).

## The queue file: `documents.md`

Generated by `edoc` (fetch). Plain markdown, two flag concepts:

```markdown
# eDoc Signing Queue

**Queue Status:** `PROVISIONAL`           ← global gate; flip to READY to sign
**Generated:** 2026-05-08 15:30
**Inbox:** ผศ. ดร. ณยศ คุรุกิจโกศล
**Total:** 23 documents

> Default command: ดำเนินการตามเสนอ

---

## 1. ขอให้พิจารณารับรองวุฒิ ...

- **Data ID:** `29777084`
- **Action:** `signing`                  ← change to `skip` to leave untouched
- **Command:** ดำเนินการตามเสนอ           ← edit per-doc signing command
- **AI reasoning:** ต้องพิจารณารับรองวุฒิ; ผู้ส่งระดับมหาวิทยาลัย
- **Summary:** ...

---

## 2. ...
```

### Editing rules

- **Queue Status** must be exactly `PROVISIONAL` or `READY` (case-insensitive,
  with or without backticks). Anything else → exit 2 with a pointed error.
- **Action** must be exactly `signing` or `skip`. Anything else → fatal error
  naming the offending block. (The strict check is intentional — better to
  refuse than silently mis-sign.)
- **Command** is free Thai text. Empty falls back to `ดำเนินการตามเสนอ`.
- **Data ID** lines must be unique; duplicates → fatal error.
- Field labels are case-insensitive. Markdown fences, ordering of fields, and
  extra whitespace within blocks are all tolerated.

### Re-fetching while a queue exists

If `documents.md` already exists with `Queue Status: READY`, `edoc` refuses to
overwrite it (so you don't lose authorisation edits). Either:

- run `edoc --sign` first, or
- reset the gate to `PROVISIONAL`, or
- pass `--force` to overwrite anyway.

While the gate is `PROVISIONAL`, fetch overwrites freely.

## Files produced

| Path                                | Owner   | Purpose |
|-------------------------------------|---------|---------|
| `documents.md`                      | edoc    | Editable queue. Moved to `log/` after a real sign. |
| `documents_data.json`               | edoc    | Raw scrape cache. Used by `--from-cache` and to attach notes to history. |
| `signing_history.json`              | edoc    | Last 100 signed docs; fed to Claude as few-shot examples on next analysis. |
| `edoc_automation.log`               | edoc    | Timestamped action log (login, click, sign, error). |
| `screenshots/`                      | edoc    | One PNG per major step (inbox, sign form before/after, error states). |
| `log/documents_*.md`                | edoc    | Archived queue files from completed sign runs. |
| `ai_response_raw.txt`               | edoc    | Only written when Claude's JSON fails to parse, for debugging. |

`documents_data.json`, `signing_history.json`, and the screenshots folder
should be in `.gitignore`. The credentials live in `.env` — never commit it.

## Troubleshooting

**"Queue Status is 'PROVISIONAL', not READY."**
You ran `--sign` before flipping the top-of-file gate. Open `documents.md`,
change `**Queue Status:** \`PROVISIONAL\`` to `**Queue Status:** \`READY\``, save.

**"Refusing to overwrite documents.md: Queue Status is READY."**
You ran fetch over a file you'd already authorised. Sign it (`edoc --sign`),
flip the gate back to `PROVISIONAL`, or pass `--force`.

**"Action must be 'signing' or 'skip', got 'foo'"**
A block has a typo in its Action line. The error names the offending Data ID;
fix that block and re-run.

**Sign dialog never appeared** (logged per doc)
The portal occasionally fails to open the sign frame. The signer retries the
whole flow up to 3× per document and saves debug screenshots
(`screenshots/phase5_debug_*.png`) before giving up. Re-running picks up the
failed docs from the inbox.

**Session expired mid-run**
Each `edoc` invocation logs in fresh, so just re-run.

**Headful vs headless**
Use `--headful` while iterating; switch to `--headless` (or set
`HEADLESS=true` in `.env`) for unattended runs.

## Project layout

```
edocAutomation/
├── edoc/                      ← the CLI package
│   ├── cli.py                 ← argparse, flow orchestration, progress UI
│   ├── config.py              ← .env loader + HEADLESS resolution
│   ├── browser.py             ← login / iframe / sign-frame helpers
│   ├── inbox.py               ← scrape inbox + read each doc
│   ├── analyzer.py            ← Claude call + history bookkeeping
│   ├── signer.py              ← per-doc sign flow with retries
│   ├── docfile.py             ← documents.md writer + parser
│   └── log.py                 ← logging setup
├── phase1_login.py … phase5_sign.py  ← legacy standalone scripts (recon / fallback)
├── app.py                     ← FastAPI web UI (separate front-end, optional)
├── pyproject.toml             ← `[project.scripts] edoc = "edoc.cli:main"`
├── .env / .env.example        ← credentials + HEADLESS
├── CLAUDE.md                  ← project notes for Claude Code
└── README.md                  ← this file
```

The legacy `phase*.py` scripts are kept for ad-hoc recon (selector inspection,
debugging a single phase) and as a fallback if the CLI ever breaks. They share
no code with `edoc/`; the helpers in `edoc/browser.py` are clean re-extractions.
